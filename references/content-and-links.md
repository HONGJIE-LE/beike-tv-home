# 首页内容与入口确认

## 内容

填assets/homepage-confirmation.md。已有明确选择记为已确认，缺失、冲突或影响效果的项目合并为一至两个问题。用户确认具体内容与入口，不是授权全部系统改动。

应确认标题、地点、标语、Logo版本与来源、背景风格、配色、主入口数量与顺序、图标与说明、辅助入口，以及遥控器各键行为。应用数量决定布局，不能把案例中的两入口变成限制。

时间、网络状态、Wi-Fi/系统设置可建议保留，但以用户选择为准。开机、待机唤醒、主页键目标分别记录。仅修改某个按钮或链接时不重开全部确认。

## 每条入口的真实目标

| 类型 | 需确认与验证 |
|---|---|
| 已安装应用 | 真实显示名、包名、启动Activity/Intent、启用状态、实际打开 |
| 新APK | 可信来源、签名/更新关系、ABI、minSdk、是否保留数据 |
| 网页 | 完整URL、发布/预览、路由、地点、登录要求和实际加载 |
| 投屏 | 本机投屏入口、用户需要的设备/协议；应用打开与实际投屏分开验收 |
| 系统设置 | 当前系统支持的Action/Activity和实际面板，不触碰未请求配置 |

多个候选应用给用户选择，不擅自安装替代投屏工具。没有LAUNCHER入口不代表不能打开，可以查合法导出Activity或厂商Intent；不试开工厂或产测界面。

## 网页确认易错点

- 显示文字、实际URL和跳转结果可能不同，核对真正目标。
- 参数和fragment不能丢，例如地点可能位于`#/display?place=...`。
- 页面写“仅供预览”时告知并确认是否继续使用；不擅自发布项目以获得正式链接。
- 链接可打开不代表权限、业务数据正常；电视与电脑登录独立，由用户扫码确认。
- 换域名后重新验证登录与最终路由，登录成功后可能进入管理后台而不是展示页。
- 构建前用对应表确认尚未明确的链接与目标，不使用历史项目名称或URL代填。

## 显示与操作

分别验证应用启动、页面出现和业务功能。退出码成功或前台Activity变化不能替代实际画面。

网页没有焦点导航时，可给用户选择遥控鼠标或外接鼠标，不把光标能动当作全部操作适配。

自绘首页检查文字、边距、焦点、触摸区域和遥控顺序。ARGB设置后再强制setAlpha(255)会使半透明装饰变白块，应实机检查。Wi-Fi侧边面板可能不改变前台Activity，应看真实画面。网络状态不要把“有网络”误报成“已验证互联网可达”。
