# 设备验证流程

## 先收集，再读取

先问品牌、具体型号、当前IP，确认电脑与电视同网。询问USB设备和USB网卡，避免调试状态影响供电。缺IP时指导查看网络详情，不能把802.11等Wi-Fi协议当作IP。

只连接用户指定设备。普通IPv4前导零可规范化并告知实际地址，不猜网段，不扫描无关设备。

从项目说明检查真实安装要求，复用已有Python、JDK、Android SDK、ADB和签名工具，按需补齐。不要机械安装一整套过时依赖。

## 必须核实的设备事实

| 项目 | 用途 |
|---|---|
| 实际model、manufacturer、device、固件、Android版本和SDK | 判断平台，营销型号仅作补充 |
| ABI列表 | 判断32/64位APK |
| 屏幕、密度及覆盖值 | 避免缩放和裁切错误 |
| 原厂HOME解析、真实前台组件 | 识别启动机制并准备恢复 |
| 包列表、禁用列表、剩余空间 | 发现真实应用入口和安装条件 |
| WebView提供者及版本（网页任务） | 判断现代网页兼容性 |
| 网络和调试状态 | 区分断网、关闭端口、未授权、端口变化和电脑权限 |

可使用可靠项目探测工具，或标准只读ADB命令：

```sh
adb -s <已确认设备> shell getprop ro.product.model
adb -s <已确认设备> shell getprop ro.product.manufacturer
adb -s <已确认设备> shell getprop ro.build.version.sdk
adb -s <已确认设备> shell getprop ro.product.cpu.abilist
adb -s <已确认设备> shell wm size
adb -s <已确认设备> shell wm density
adb -s <已确认设备> shell dumpsys webviewupdate
adb -s <已确认设备> shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

不支持某条命令时依据版本选只读替代方式，不把命令缺失当作设备不兼容。

## 按系统分支，不按品牌套用

| 场景 | 处理 |
|---|---|
| Android TV / Google TV | 验证SDK、安装权限和调试方式后继续 |
| 国产定制安卓系统 | 额外检查原生启动/后台管理，不假定标准HOME有效 |
| 海信等品牌的VIDAA | 不走安卓APK安装，核实该机型可用的展示路线 |
| 其他非安卓系统 | 同样先确认平台能力，不反复执行安卓工具 |
| 系统不确定 | 保留未知结论，取得实际系统信息后继续 |

创维、小米、海信等的设置路径、ADB重启后行为、自启及后台策略，都应在本机固件验证，不能凭品牌推断。

## 有界排查

- 默认端口拒绝：确认开关，必要时查看无线调试配对/连接端口，不连续重试同一关闭端口。
- 授权：提前提醒用户留意电视授权窗口。
- 电脑连接受限：区分本地网络权限/执行环境与电视问题，不能把“无路由”直接当作电视不兼容。
- 重启后断开：等待启动，检查屏幕、网络和当前IP，不在连接未恢复时盲目修改。
- 安装自动拒绝：看提示和日志；若确认超时，等用户准备后再触发一次。系统明确不支持或验证拒绝时停止这条路线。

## 备份

首次修改前保存包列表、禁用列表、系统属性、相关settings、原Home组件和即将修改的按应用启动策略。恢复使用本机原值，不复制其他型号配置。

不得禁用原厂桌面、输入源、蓝牙遥控、键盘、设置、安装器或权限控制等核心组件。工厂、产测、维修程序不能作探测入口。普通首页任务不包括root、刷机或改写系统分区。
