# 启动配置、验证与恢复

开机进入应用、待机唤醒进入首页、主页键进入首页是三个独立目标。确定启动目标后，避免多个开机接收器争抢画面。

## 原生设置优先

先查本机的按应用自启动、后台保留或省电管理。允许装APK不等于允许开机进程或后台运行。BOOT_COMPLETED、前台常驻和无障碍都可能被厂商清理。

按应用调整，保存原值并读回。正常系统设置能完成时，不修改数据库或系统文件。不移用别的型号的Binder编号、属性或厂商伪装包名。

有Boot Denial、后台强制停止、辅助服务清空等证据时，先寻找对应原生管理入口。没有新证据，不反复叠加延迟、常驻和轮询。

### 创维特定案例入口

先只读解析，再决定是否使用：

```sh
adb -s <已确认设备> shell cmd package resolve-activity --brief -a coocaa.intent.action.APP_STARTUP_LIST
```

本次55R7H实测解析到：

`com.coocaa.os.softsettings/com.tianci.setting.startup.ui.AppStartupListActivity`

原生界面中只为目标首页打开“允许后台自启动”，将后台策略改为“保持后台运行”。这是本机经过UI验证的入口，不保证其他创维型号存在，更不能套到小米或海信。

## 验收顺序

1. 首页可显示，打开过一次，未处于force-stopped状态。
2. 原生启动/后台策略已确认，目标是本次选择的首页。
3. 模拟延迟拉起只算集成测试，不算开机验收。
4. 一次实际系统重启后结合截图、最终停留画面和用户确认，必要时辅以开机广播记录。
5. 待机唤醒、断电冷启动与系统重启分别标状态，不扩大结论。
6. 网络、调试连接、启动画面分别记录。首页可离线显示，不应把网络异常误判成首页没启动。

远程重启前告知画面中断。发现同一种重启方式造成Wi-Fi关闭或无法开启，就停止重复使用，先恢复网络、保存日志。不能靠反复重启碰运气。

## 主页键与权限

用户要求主页键接管时才考虑额外辅助服务。先完成可审阅页面，再说明需要的权限、实际监听范围、内容读取/按键过滤范围和关闭方法。

授权效果不等于授权高权限设置。自动审批拒绝时，不换方式偷偷开启；完成其他已授权工作，说明拒绝动作与原因，再取得必要确认。权限范围不变、用户已明确授权的修复不要重复询问。

保留已有辅助服务列表，不覆盖成自己的服务。Enabled、Bound、进程存活和真实按键效果分别检查。模拟按键不能替代用户按真实遥控器。

## 恢复与交付

保留原厂桌面及核心组件。恢复步骤覆盖默认Home、辅助服务、启动策略和自建开机入口，不能只改一项后仍自动跳回。

若恢复工具需卸载自建普通应用，应事先说明并在运行前确认，保留业务应用及登录数据。不是所有方案都需卸载；系统组件不得卸载。

更新尽量保持应用标识与签名，变更会影响数据时明确告知。依赖要求按当前官方文档验证，不把历史版本号当作永久要求。

报告准确状态：已构建、已安装、入口已打开、真实按键通过、本次系统重启通过。设置已开启不等于最终成功。
