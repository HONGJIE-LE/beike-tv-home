# 2026-11-16：创维55R7H实测案例

设备报告7AA49_R7H、T963、安卓9/API28、armeabi-v7a、1920×1080。结论限于这台设备及当时固件，不能推广成品牌能力。

## 制作与入口

制作了原生品牌首页和独立网页展示应用，含签约中心、电视自带投屏、Wi-Fi/系统设置。业务链接先为预览版，后由用户换成带地点参数的发布链接；这些业务名称和URL不成为下一项目默认值。

- 电脑装好工具不等于装到电视，需真实IP与调试连接。
- 本机WebView仅66版，现代网页改用独立引擎；不是所有电视都需要相同引擎。
- 电视独立扫码登录，电脑会话不能当作电视登录证据。登录后曾进入管理后台，需再次核对目标展示路由。
- 新应用安装约10秒自动拒绝，日志为auto_refuse；等用户准备并及时确认后安装成功，不是兼容性失败。
- Canvas透明度被强制设为255曾造成白块，实机发现后修正。
- Wi-Fi是侧边覆盖面板，前台Activity可能仍为首页。
- 投屏没有标准LAUNCHER入口，但存在合法可启动界面；该包名不作为其他电视默认值。

## 开机的真实解决点

标准默认Home返回Success，但实际主页键仍走厂商路径。普通开机接收、延迟、无障碍及前台常驻未能单独稳定解决。日志明确有SkyRMService强制停止首页并清掉辅助服务。

后来确认本机存在`coocaa.intent.action.APP_STARTUP_LIST`，原生列表显示首页“不允许后台自启动、智能控制后台运行”。仅将该应用改为“允许后台自启动、保持后台运行”后：

1. 打开业务应用并等待15秒，首页进程仍在，stopped=false。
2. 本次系统重启后，用户确认自动进入首页。
3. 系统事件记录显示进程因HomeBootReceiver开机广播启动，随后创建并显示HomeActivity。
4. 按用户最后要求不再处理主页键，辅助功能未重新开启。

成功来自原生按应用策略，不是单纯增加服务或反复声明HOME。操作在原生UI完成，没有直接套用其他机型的Binder写事务、数据库或系统属性。

## 限制与后续

电脑发起重启后，Wi-Fi多次关闭或暂时无法开启。用户手动恢复后可用。日志有无线模块初始化报错，但无法据此确定关闭原因；没有将其归咎于首页或某个系统组件。停止电脑重启，保留已成功配置。

仅通过一次系统重启。遥控器开关、断电冷启动、长期稳定性、业务叫号语音、实际手机投屏未完整验证，不能写成全部成功。

百变艺术屏通过正常设置中的“壁纸开关”关闭，没有禁用整个系统包。
